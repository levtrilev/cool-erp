## 🎯 О проекте

**Cool ERP** — это корпоративная система управления документами и правами доступа, построенная на принципах **«явное управление» и «безопасность по умолчанию»**. Ни один слой доступа не предоставляет прав «по умолчанию» и не снимает ограничений автоматически.

Ключевые особенности:
- 🔐 **Гибридная модель доступа** (ТЗ §8): роли × разделы × типы документов × теги × уровни
- 🏢 **Полная изоляция данных** между организациями (мульти-тенантность на уровне SQL)
- 📄 **Универсальный документный контракт** — единая модель для любых типов документов
- ⚡ **Двухуровневая система блокировок** — оптимистическая (`version` → 409) + пессимистическая (`/lock` → 423)
- 🏷️ **Тег-ориентированная видимость** — документы с тегами `регион:сибирь`, `гриф:секретно` видны только обладателям соответствующих допусков

## ✨ Ключевые возможности

### 🔒 Двухуровневая защита документов
Каждый документ защищён двумя механизмами:
- **Пессимистическая блокировка** — при открытии документа вызывается `POST /{doctype}/{id}/lock`. Если документ занят, пользователь получает режим «только чтение» с предупреждением. Таймаут 30 минут защищает от «забытых» блокировок.
- **Оптимистическая блокировка** — при сохранении проверяется поле `version`. Если документ изменился параллельно — конфликт 409 без перезаписи.

### 📋 Документный контракт (ТЗ §3.3)
Любой тип документа наследует два миксина и автоматически получает **17 полей** контракта:
- `DocumentAccessMixin` — `tenant_id`, `section_id`, `author_id`, `or_tags`, `and_tags`
- `DocumentLifecycleMixin` — `version`, `editing_by_user_id`, `doc_status`, `deleted_at` и др.

### 🎨 Единообразный интерфейс
Все документные модули используют паттерн **«название-ссылка»** (Правило №39): клик по названию открывает форму редактирования с захватом блокировки. Отдельная кнопка «Редактировать» не нужна — колонка «Действия» сокращается до 80px.

### 🧩 Оркестрация правил
Разработка ведётся по **строгому своду из 42 правил**, покрывающих:
- Типобезопасность на всех слоях (от моделей до API)
- Паттерны форм, поиска, модалок, таблиц
- Мультиарендность на уровне SQL
- Обработку ошибок и уведомления

## 🚀 Что дальше

### Ближайшие задачи:
1. **Модуль `sections`** — Разделы с тремя типами (платформенный / общий организации / произвольный)
2. **`AccessService`** — реализация алгоритма §8 ТЗ (вычисление `visible` + `level` + `can_delete`)
3. **Тег-инфраструктура** — фильтрация через GIN-индексы, правило «нет тегов → виден только уровень 4»
4. **Делегирование** — временная передача прав на конкретные документы (§11)

### Стратегические цели:
- Полный аудит конфигурации доступов и данных (§12)
- Отчёты «Карта доступов», «Изменения за период», детектор «сирот» (§12.1.6)
- Интеграция с СЭД/КЭП для подтверждения субъекта операции (§18.9)
