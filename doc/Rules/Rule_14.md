# Правило №14: Первая колонка как ссылка для редактирования

Первая колонка (обычно содержащая название, имя или идентификатор сущности) в таблицах на списочных CRUD-страницах **ОБЯЗАТЕЛЬНО** должна быть кликабельной ссылкой, открывающей модалку редактирования. 

Использование отдельной кнопки «Редактировать» (иконка карандаша) в колонке действий **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО**.

---

### 1. Обоснование (Почему это важно)

1. **Общепринятый UX-стандарт:** В современных интерфейсах (Jira, GitHub, админ-панели SaaS) пользователи интуитивно ожидают, что основной идентификатор записи (её название) является кликабельным. Отдельная кнопка «Редактировать» воспринимается как архаизм и визуальный шум.
2. **Экономия пространства:** Колонка действий (Actions) часто перегружена. Убирая из неё кнопку редактирования, мы освобождаем место для действительно важных действий (например, «Просмотр», «Клонировать») или просто делаем интерфейс чище.
3. **Закон Фиттса:** Первая колонка обычно содержит самый длинный текст и занимает больше всего места. Превращая её в ссылку, мы создаем огромную область клика (click target), что повышает удобство использования.

---

### 2. Обязательные требования к реализации

#### 2.1. Визуальное оформление
Элемент в первой колонке должен выглядеть как гиперссылка:
* Цвет текста: акцентный (обычно синий, `text-blue-600`).
* При наведении: изменение цвета (`hover:text-blue-800`) и появление подчеркивания (`hover:underline`).
* Курсор: `cursor-pointer`.

#### 2.2. Техническая реализация (SPA)
Несмотря на визуальное сходство с тегом `<a>`, **НЕЛЬЗЯ** использовать `<a href="...">`, так как это вызовет полный перезагрузку страницы. Необходимо использовать `<button type="button">`, стилизованный под ссылку.

#### 2.3. Отсутствие дублирования
В колонке действий (последняя колонка с иконками) **НЕ ДОЛЖНО** быть кнопки или иконки редактирования (`Edit2`, `Pencil`). Там должны оставаться только деструктивные действия (Корзина) или второстепенные.

---

### 3. Примеры кода

#### ✅ ПРАВИЛЬНО: Первая колонка как кнопка-ссылка

```tsx
<TableRow key={role.id}>
  {/* ✅ ПЕРВАЯ КОЛОНКА: Кликабельное название */}
  <TableCell className="py-2 align-top overflow-hidden">
    <button
      type="button" // ✅ Обязательно, чтобы не сабмитить форму, если таблица внутри <form>
      onClick={() => handleEdit(role)}
      title={role.name} // ✅ Тултип для обрезанного текста
      className="block w-full text-left text-blue-600 hover:text-blue-800 hover:underline cursor-pointer font-medium truncate"
    >
      {role.name}
    </button>
  </TableCell>

  {/* ... остальные колонки ... */}

  {/* ✅ КОЛОНКА ДЕЙСТВИЙ: Только удаление (или другие второстепенные действия) */}
  <TableCell className="py-2 align-top">
    <Button
      variant="ghost"
      size="icon"
      onClick={() => setDeleteRoleId(role.id)}
    >
      <Trash2 className="h-4 w-4" />
    </Button>
    {/*  Здесь НЕ должно быть кнопки <Edit2 /> */}
  </TableCell>
</TableRow>
```

#### ❌ НЕПРАВИЛЬНО: Отдельная кнопка редактирования

```tsx
<TableRow key={role.id}>
  {/* ❌ ОШИБКА: Название просто текст, не кликабельно */}
  <TableCell className="py-2">{role.name}</TableCell>

  {/* ... */}

  {/* ❌ ОШИБКА: Дублирование действий, визуальный шум в колонке действий */}
  <TableCell className="py-2">
    <Button variant="ghost" size="icon" onClick={() => handleEdit(role)}>
      <Edit2 className="h-4 w-4" /> {/* ❌ ЗАПРЕЩЕНО */}
    </Button>
    <Button variant="ghost" size="icon" onClick={() => setDeleteRoleId(role.id)}>
      <Trash2 className="h-4 w-4" />
    </Button>
  </TableCell>
</TableRow>
```

#### ❌ НЕПРАВИЛЬНО: Использование тега `<a>`

```tsx
// ❌ ОШИБКА: Вызовет перезагрузку всей SPA-страницы и потерю состояния
<a href={`/roles/${role.id}/edit`} className="text-blue-600 hover:underline">
  {role.name}
</a>
```

### 4. Нюансы и лучшие практики

#### 4.1. Интеграция с изменяемыми колонками (Правило №29)
Поскольку ширина первой колонки может меняться пользователем, кнопка-ссылка должна занимать всю доступную ширину ячейки (`block w-full`). Это гарантирует, что клик сработает в любой точке ячейки, а не только на самом тексте.

#### 4.2. Обрезка длинного текста (Truncate)
Если название сущности очень длинное, оно должно обрезаться с троеточием (см. предыдущие правила о таблицах). Атрибут `title={role.name}` обеспечит нативную всплывающую подсказку при наведении, чтобы пользователь мог прочитать полное название.

#### 4.3. Выделение жирным шрифтом
Для улучшения визуальной иерархии текст в первой колонке часто делают полужирным (`font-medium` или `font-semibold`), чтобы отделить идентификатор от описания во второй колонке.

### 5. Чек-лист для разработчика

При верстке таблицы на списочной странице проверьте:

- [ ] Является ли первая колонка кликабельным элементом (`<button type="button">`)?
- [ ] Стилизована ли она как ссылка (`text-blue-600`, `hover:underline`)?
- [ ] Имеет ли она классы `block w-full text-left` для корректной работы с изменяемой шириной колонки?
- [ ] **Отсутствует** ли кнопка/иконка редактирования в последней колонке (Actions)?
- [ ] Добавлен ли атрибут `title` для отображения полного текста при обрезке (`truncate`)?
- [ ] Используется ли `type="button"` для предотвращения случайной отправки форм?

Следование этому правилу делает интерфейс Cool ERP современным, чистым и интуитивно понятным для пользователей, привыкших к лучшим мировым практикам UX.
