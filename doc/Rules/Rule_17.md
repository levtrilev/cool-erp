# Правило №17: Подсветка строки после создания/обновления

После успешного создания или обновления записи соответствующая строка в таблице **ОБЯЗАТЕЛЬНО** должна подсвечиваться (обычно желтым или акцентным цветом) на ограниченное время (3 секунды). Это дает пользователю мгновенную и понятную визуальную обратную связь о том, где физически находится только что измененный объект.

---

### 1. Обоснование (Почему это важно)

1. **Визуальное подтверждение действия:** Пользователь нажал «Сохранить», модалка закрылась. Подсветка строки — это недвусмысленный сигнал: «Да, система приняла изменения, и вот они».
2. **Помощь в навигации:** При сортировке списка (например, по алфавиту) новая или измененная запись может переместиться из конца списка в середину. Подсветка помогает пользователю мгновенно найти её глазами, не сканируя весь список.
3. **Снижение когнитивной нагрузки:** Пользователю не нужно вчитываться в текст toast-уведомления или вспоминать, как именно он назвал только что созданный объект.

---

### 2. Обязательные требования к реализации

#### 2.1. Состояние подсветки
В компоненте списочной страницы **ОБЯЗАТЕЛЬНО** должно быть объявлено состояние для хранения ID подсвечиваемой записии (согласно Правилу №22):
```tsx
const [highlightedRoleId, setHighlightedRoleId] = useState<string | null>(null);
```

#### 2.2. Условный CSS-класс на `TableRow`
К строке таблицы (`TableRow`) **ОБЯЗАТЕЛЬНО** применяется условный класс. Цвет подсветки должен быть заметным, но не перекрывать текст, и **обязательно** поддерживать темную тему.
* Рекомендуемые классы: `bg-yellow-100 dark:bg-yellow-900/30 transition-colors duration-300`

#### 2.3. Автоматический сброс (Таймер)
Подсветка **НЕ ДОЛЖНА** оставаться навсегда. Через 3000 миллисекунд (3 секунды) состояние подсветки должно быть сброшено в `null`.

---

### 3. Примеры кода

#### ✅ ПРАВИЛЬНО: Полная реализация подсветки

**1. Инициализация состояния:**
```tsx
const [highlightedRoleId, setHighlightedRoleId] = useState<string | null>(null);
```

**2. Применение к строке таблицы (`TableRow`):**
```tsx
{roles.map((role) => (
  <TableRow
    key={role.id}
    // ✅ Условная подсветка с плавным переходом
    className={
      highlightedRoleId === role.id
        ? "bg-yellow-100 dark:bg-yellow-900/30 transition-colors duration-300"
        : ""
    }
  >
    <TableCell>{role.name}</TableCell>
    {/* ... остальные ячейки ... */}
  </TableRow>
))}
```

**3. Запуск подсветки (внутри обработчика сохранения или `useEffect`):**
```tsx
// Вариант А: Прямой вызов после успешного сохранения на текущей странице
const handleRoleSaved = (id: string) => {
  setHighlightedRoleId(id);
  // ✅ Сброс через 3 секунды
  setTimeout(() => setHighlightedRoleId(null), 3000); 
};

// Вариант Б: Через useEffect (Рекомендуется для навигации с других страниц, см. Правило №18)
useEffect(() => {
  if (highlightedRoleId && data?.data?.items?.some(item => item.id === highlightedRoleId)) {
    const timer = setTimeout(() => setHighlightedRoleId(null), 3000);
    return () => clearTimeout(timer); // ✅ Очистка таймера при размонтировании
  }
}, [data, highlightedRoleId]);
```

#### ❌ НЕПРАВИЛЬНО: Типичные ошибки

**1. Подсветка без таймера (Вечная подсветка):**
```tsx
// ❌ ОШИБКА: Строка останется желтой навсегда, пока пользователь не перезагрузит страницу.
setHighlightedRoleId(id); 
```

**2. Неправильное применение класса:**
```tsx
// ❌ ОШИБКА: Подсветка только одной ячейки выглядит как баг. Подсвечивать нужно ВСЮ строку (TableRow).
<TableCell className="bg-yellow-100">{role.name}</TableCell> 

// ❌ ОШИБКА: Отсутствие поддержки темной темы (dark:). На темном фоне желтый будет "выжигать" глаза.
className="bg-yellow-300" 
```

**3. Использование `alert()` или блокировка UI:**
```tsx
// ❌ ОШИБКА: Блокирующие уведомления прерывают рабочий процесс.
alert("Роль создана! Найдите её в списке."); 
```

---

### 4. Нюансы и лучшие практики

#### 4.1. Плавность переходов
Обязательно добавляйте класс `transition-colors duration-300` к `TableRow`. Это сделает исчезновение подсветки плавным (fade-out), что выглядит гораздо профессиональнее, чем резкое мигание.

#### 4.2. Интеграция с умной навигацией (Правило №18)
Если пользователь создает запись, находясь на 1-й странице, а запись попадает на 3-ю, он нажмет кнопку «Перейти» в toast-уведомлении. 
В этом случае `setPage(3)` вызовет загрузку новых данных. Чтобы запись подсветилась **после** загрузки, используйте `useEffect` (Вариант Б из примера выше), который сработает, как только `data` обновится и запись появится в DOM.

#### 4.3. Цветовая палитра
Используйте стандартные семантические цвета Tailwind:
* `bg-yellow-100` / `dark:bg-yellow-900/30` — для стандартного выделения (создание/обновление).
* `bg-green-100` / `dark:bg-green-900/30` — допустимо для подтверждения критически важных успешных операций.
* Избегайте красных (`bg-red-...`) и синих (`bg-blue-...`) цветов для подсветки строк, так как они могут конфликтовать с цветами ошибок или ссылок.

---

### 5. Чек-лист для разработчика

При реализации списочной страницы проверьте:

- [ ] Объявлено ли состояние `highlightedXxxId`?
- [ ] Применяется ли условный класс к компоненту `TableRow` (а не к `TableCell`)?
- [ ] Содержит ли класс поддержку темной темы (`dark:bg-...`)?
- [ ] Добавлен ли класс `transition-colors duration-300` для плавности?
- [ ] Реализован ли механизм автоматического сброса подсветки через 3000мс (`setTimeout`)?
- [ ] Очищается ли таймер в `useEffect` (через `clearTimeout`), если используется реактивный подход?

Следование этому правилу превращает сухое CRUD-приложение в отзывчивый и дружелюбный интерфейс, который всегда «разговаривает» с пользователем на языке визуальных подсказок.
