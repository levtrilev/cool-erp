# Правило №12: Поиск через form

Поле поиска на всех списочных CRUD-страницах **ОБЯЗАТЕЛЬНО** должно быть обёрнуто в HTML-тег `<form>` с обработчиком `onSubmit`. Это обеспечивает перехват нажатия клавиши Enter и выполнение поиска без необходимости кликать по кнопке «Найти».

Использование «голого» `<Input>` без формы, а также поиск по каждому введённому символу (без явного подтверждения) **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО**.

---

### 1. Обоснование (Почему это важно)

1. **Эргономика клавиатуры:** Опытные пользователи ERP-систем работают преимущественно с клавиатуры. Нажатие Enter — это самый быстрый способ выполнить поиск. Если его не поддерживать, пользователь вынужден тянуться к мыши, что замедляет работу.
2. **Разделение состояний (Performance):** Поиск по каждому символу (onChange) генерирует огромное количество запросов к бэкенду при быстром вводе, создавая лишнюю нагрузку на сервер и вызывая «мигание» таблицы. Обёртка в `<form>` естественным образом разделяет процесс ввода и процесс запроса.
3. **Семантическая валидность HTML:** Использование `<form>` для группы связанных полей ввода — это стандарт HTML. Браузеры и screen reader'ы корректно интерпретируют такую разметку, что улучшает доступность.
4. **Единообразие UX:** Во всех местах приложения (поиск ролей, пользователей, разделов) пользователь будет ожидать одинакового поведения — Enter выполняет поиск.

---

### 2. Обязательные требования к реализации

#### 2.1. Разделение состояний (Связь с Правилом №22)
В компоненте **ОБЯЗАТЕЛЬНО** должны быть объявлены две отдельные переменные состояния:
* `searchInput: string` — значение, которое пользователь вводит в текстовое поле (контролируемый инпут).
* `search: string` — значение, которое фактически отправляется на бэкенд. Обновляется только при подтверждении (Enter или клик по кнопке).

#### 2.2. Обёртка в `<form>`
Поле поиска и кнопка «Найти» **ОБЯЗАТЕЛЬНО** должны быть обёрнуты в тег `<form>`.

#### 2.3. Обработчик `onSubmit`
На форме **ОБЯЗАТЕЛЬНО** должен быть обработчик `onSubmit`, который:
* Вызывает `e.preventDefault()` для предотвращения перезагрузки страницы.
* Копирует значение из `searchInput` в `search`.
* Сбрасывает пагинацию на первую страницу (`setPage(1)`).

#### 2.4. Кнопка отправки
Кнопка «Найти» **ОБЯЗАТЕЛЬНО** должна иметь атрибут `type="submit"`. Это позволяет ей срабатывать при нажатии Enter в поле ввода.

---

### 3. Примеры кода

#### ✅ ПРАВИЛЬНО: Полная реализация поиска

```tsx
import { useState } from "react";
import { Input } from "@/components/ui/input";
import { Button } from "@/components/ui/button";
import { Search, X } from "lucide-react";

export const RolesPage = () => {
  // ✅ РАЗДЕЛЕНИЕ СОСТОЯНИЙ (Правило №22)
  const [searchInput, setSearchInput] = useState("");
  const [search, setSearch] = useState("");
  const [page, setPage] = useState(1);

  // Обработчик подтверждения поиска
  const handleSearch = (e: React.FormEvent) => {
    e.preventDefault(); // ✅ Предотвращаем перезагрузку страницы
    setSearch(searchInput); // ✅ Обновляем запрос
    setPage(1); // ✅ Сбрасываем на первую страницу
  };

  // Обработчик очистки поиска
  const handleClearSearch = () => {
    setSearchInput("");
    setSearch("");
    setPage(1);
  };

  return (
    <div className="container mx-auto px-4 py-3">
      {/* Заголовок страницы */}
      <div className="flex justify-between items-center mb-2">
        <h1 className="text-xl font-bold">Роли</h1>
        <Button>Создать роль</Button>
      </div>

      {/* ✅ БЛОК ПОИСКА, ОБЁРНУТЫЙ В <form> */}
      <form onSubmit={handleSearch} className="flex gap-2 mb-2">
        <div className="relative flex-1 max-w-sm">
          <Input
            value={searchInput}
            onChange={(e) => setSearchInput(e.target.value)}
            placeholder="Поиск по названию..."
            className="pl-9"
          />
          {/* Иконка поиска слева */}
          <Search className="absolute left-3 top-1/2 -translate-y-1/2 h-4 w-4 text-muted-foreground" />
          
          {/* ✅ Кнопка очистки (если есть текст) */}
          {searchInput && (
            <button
              type="button"
              onClick={handleClearSearch}
              className="absolute right-3 top-1/2 -translate-y-1/2 text-muted-foreground hover:text-foreground"
            >
              <X className="h-4 w-4" />
            </button>
          )}
        </div>

        {/* ✅ Кнопка "Найти" с type="submit" */}
        <Button type="submit" variant="secondary">
          Найти
        </Button>
      </form>

      {/* Таблица использует значение search (не searchInput!) */}
      <Table>
        {/* ... */}
      </Table>
    </div>
  );
};
```

#### ❌ НЕПРАВИЛЬНО: Поиск по каждому символу (Антипаттерн)

```tsx
// ❌ ГРУБОЕ НАРУШЕНИЕ ПРАВИЛА №12
<Input
  value={search}
  onChange={(e) => {
    setSearch(e.target.value); // ❌ Запрос на каждый символ!
    setPage(1);
  }}
  placeholder="Поиск..."
/>
```
*Почему это плохо:* При вводе слова «Администратор» (13 символов) будет отправлено 13 запросов к бэкенду. Это создаёт лишнюю нагрузку, вызывает «мигание» таблицы и может привести к race condition (когда более медленный ранний запрос перезаписывает результат более быстрого позднего).

#### ❌ НЕПРАВИЛЬНО: Отсутствие обёртки `<form>`

```tsx
// ❌ ОШИБКА: Enter не работает, пользователь вынужден кликать по кнопке
<div className="flex gap-2">
  <Input
    value={searchInput}
    onChange={(e) => setSearchInput(e.target.value)}
    placeholder="Поиск..."
  />
  {/* ❌ Кнопка без type="submit" и без формы */}
  <Button onClick={() => { setSearch(searchInput); setPage(1); }}>
    Найти
  </Button>
</div>
```

#### ❌ НЕПРАВИЛЬНО: Отсутствие `e.preventDefault()`

```tsx
// ❌ ОШИБКА: Страница перезагрузится при нажатии Enter
<form onSubmit={() => {
  setSearch(searchInput); // ❌ Нет e.preventDefault()!
  setPage(1);
}}>
  <Input value={searchInput} onChange={(e) => setSearchInput(e.target.value)} />
  <Button type="submit">Найти</Button>
</form>
```

### 4. Нюансы и лучшие практики

#### 4.1. Debounce как альтернатива (Допустимо, но не рекомендуется)
В некоторых случаях (например, живой поиск в справочниках) допустимо использовать debounce (задержку 300-500мс) перед отправкой запроса. Однако для основных списочных страниц Cool ERP **рекомендуется** именно явный поиск через Enter, так как это более предсказуемо для пользователя и не создаёт лишних запросов.

#### 4.2. Кнопка очистки (X)
Наличие кнопки очистки (иконка «X» внутри поля ввода) **настоятельно рекомендуется**. Она позволяет быстро сбросить поиск без необходимости вручную удалять текст. Важно: кнопка очистки должна иметь `type="button"`, чтобы не сабмитить форму.

#### 4.3. Интеграция с React Hook Form
Если поиск является частью большой формы (что редкость для списочных страниц), можно использовать `<Controller>` из react-hook-form. Однако для простого поиска достаточно нативного `<form>` и состояния.

#### 4.4. Сброс пагинации
При любом изменении поискового запроса (ввод, очистка, подтверждение) **ОБЯЗАТЕЛЬНО** сбрасывать `page` в `1`. Иначе пользователь может остаться на 5-й странице, где для нового фильтра данных уже нет.

#### 4.5. Placeholder
Текст в `placeholder` должен четко описывать, по каким полям идёт поиск:
* ✅ «Поиск по названию...»
* ✅ «Поиск по имени или email...»
* ❌ «Поиск...» (слишком абстрактно)

### 5. Чек-лист для разработчика

При добавлении поиска на любую списочную страницу проверьте:

- [ ] Объявлены ли две переменные состояния: `searchInput` и `search`?
- [ ] Обёрнут ли блок поиска в тег `<form>`?
- [ ] Есть ли обработчик `onSubmit` с вызовом `e.preventDefault()`?
- [ ] Имеет ли кнопка «Найти» атрибут `type="submit"`?
- [ ] Копируется ли значение из `searchInput` в `search` только при подтверждении?
- [ ] Сбрасывается ли `page` в `1` при подтверждении поиска?
- [ ] Используется ли `search` (а не `searchInput`) в запросе к бэкенду?
- [ ] Есть ли кнопка очистки (X) внутри поля ввода?
- [ ] Имеет ли placeholder понятное описание полей поиска?

Следование этому правилу гарантирует, что поиск во всех списках Cool ERP будет быстрым, предсказуемым и удобным для пользователей, предпочитающих работу с клавиатуры.
