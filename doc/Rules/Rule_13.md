# Правило №13: Таблица с компактным форматированием

Все таблицы на списочных CRUD-страницах **ОБЯЗАТЕЛЬНО** должны использовать единый стандарт компактного форматирования. Это обеспечивает высокую плотность информации на экране, что критически важно для десктопных интерфейсов, где пользователь работает с большими объемами данных.

---

### 1. Обоснование (Почему это важно)

1. **Плотность информации:** Стандартные компоненты таблиц (например, из Material UI или Bootstrap) часто имеют избыточные отступы. В бизнес-приложениях, где на экране одновременно отображается 10-20 строк, каждый лишний пиксель высоты — это потерянная информация, которую приходится скроллить.
2. **Единообразие UX:** Когда все таблицы в приложении (Роли, Пользователи, Тенанты, Разделы) выглядят идентично, пользователь не тратит когнитивный ресурс на адаптацию к новому интерфейсу при переходе между разделами.
3. **Визуальная иерархия:** Компактные отступы в сочетании с четкими границами (`border`) и карточным фоном (`bg-card`) создают профессиональный, "плотный" вид, характерный для корпоративных ERP-систем.

---

### 2. Обязательные требования к реализации

#### 2.1. Обёртка таблицы
Таблица **ОБЯЗАТЕЛЬНО** должна быть обернута в контейнер с классами:
```tsx
<div className="rounded-md border bg-card">
  <Table>...</Table>
</div>
```
* `rounded-md` — скругление углов (стандарт shadcn/ui).
* `border` — тонкая граница, отделяющая таблицу от фона страницы.
* `bg-card` — использование семантического цвета фона карточки (поддерживает темную тему).

#### 2.2. Заголовки таблицы (`TableHead`)
Высота строки заголовка и вертикальные отступы **ОБЯЗАТЕЛЬНО** должны быть:
```tsx
<TableHead className="h-10 py-2">...</TableHead>
```
* `h-10` — фиксированная высота строки заголовка (40px).
* `py-2` — вертикальный padding (8px сверху и снизу).

#### 2.3. Ячейки данных (`TableCell`)
Вертикальные отступы ячеек с данными **ОБЯЗАТЕЛЬНО** должны быть минимальными:
```tsx
<TableCell className="py-1">...</TableCell>
```
* `py-1` — вертикальный padding (4px сверху и снизу). Это ключевой класс для компактности.

### 3. Примеры кода

#### ✅ ПРАВИЛЬНО: Полная структура таблицы

```tsx
import {
  Table,
  TableBody,
  TableCell,
  TableHead,
  TableHeader,
  TableRow,
} from "@/components/ui/table";

export const RolesPage = () => {
  return (
    <div className="container mx-auto px-4 py-3">
      {/* Заголовок страницы */}
      <div className="flex justify-between items-center mb-2">
        <h1 className="text-xl font-bold">Роли</h1>
        <Button>Создать роль</Button>
      </div>

      {/* ✅ ПРАВИЛЬНАЯ ОБЁРТКА ТАБЛИЦЫ */}
      <div className="rounded-md border bg-card">
        <Table className="table-fixed w-full">
          <TableHeader>
            <TableRow className="h-10 hover:bg-transparent">
              {/* ✅ ЗАГОЛОВКИ С КОМПАКТНЫМИ ОТСТУПАМИ */}
              <TableHead className="w-[300px] py-2">Название</TableHead>
              <TableHead className="w-[250px] py-2">Описание</TableHead>
              <TableHead className="w-[50px] py-2"></TableHead>
            </TableRow>
          </TableHeader>
          <TableBody>
            {roles.map((role) => (
              <TableRow key={role.id} className="hover:bg-muted/50">
                {/* ✅ ЯЧЕЙКИ ДАННЫХ С МИНИМАЛЬНЫМИ ОТСТУПАМИ */}
                <TableCell className="py-1">
                  <button className="text-blue-600 hover:underline">
                    {role.name}
                  </button>
                </TableCell>
                <TableCell className="py-1 text-muted-foreground">
                  {role.description || "—"}
                </TableCell>
                <TableCell className="py-1">
                  <Button variant="ghost" size="icon">
                    <Trash2 className="h-4 w-4" />
                  </Button>
                </TableCell>
              </TableRow>
            ))}
          </TableBody>
        </Table>
      </div>
    </div>
  );
};
```

#### ❌ НЕПРАВИЛЬНО: Использование стандартных отступов shadcn/ui

```tsx
// ❌ ОШИБКА: Отсутствие обёртки с border и bg-card
<Table>
  <TableHeader>
    <TableRow>
      {/* ❌ ОШИБКА: Заголовки без явной высоты и отступов */}
      <TableHead>Название</TableHead>
      <TableHead>Описание</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    {roles.map((role) => (
      <TableRow key={role.id}>
        {/* ❌ ОШИБКА: Ячейки без py-1, таблица будет "рыхлой" */}
        <TableCell>{role.name}</TableCell>
        <TableCell>{role.description}</TableCell>
      </TableRow>
    ))}
  </TableBody>
</Table>
```

####  НЕПРАВИЛЬНО: Избыточные отступы (Антипаттерн)

```tsx
// ❌ ОШИБКА: Слишком большие отступы, таблица занимает весь экран
<TableCell className="py-4 px-6">{role.name}</TableCell>
```

### 4. Нюансы и лучшие практики

#### 4.1. Горизонтальные отступы (`px`)
Правило №13 явно регламентирует только вертикальные отступы (`py-1`, `py-2`). Горизонтальные отступы (`px`) обычно наследуются от глобальных стилей компонента `TableCell` из shadcn/ui (обычно это `px-4` или `px-2`). Если нужно дополнительно сжать таблицу по горизонтали, можно явно указать `px-2` на ячейках.

#### 4.2. Высота строки заголовка (`h-10`)
Класс `h-10` задает **фиксированную** высоту строки заголовка. Это важно для выравнивания иконки сортировки (если она есть) и для того, чтобы заголовок не "прыгал" при изменении контента.

#### 4.3. Hover-эффект на строках
Для улучшения UX добавляйте класс `hover:bg-muted/50` к `TableRow`. Это дает пользователю визуальную обратную связь при наведении на строку, что особенно важно в компактных таблицах, где строки расположены близко друг к другу.

```tsx
<TableRow className="hover:bg-muted/50">
  {/* ... */}
</TableRow>
```

#### 4.4. Выравнивание по вертикали (`align-top`)
Если в ячейках используется многострочный контент (например, список Badge'ей в колонке "Разделы"), **ОБЯЗАТЕЛЬНО** добавляйте `align-top` к `TableCell`, чтобы содержимое выравнивалось по верхнему краю, а не по центру (см. примеры с таблицей ролей).

---

### 5. Чек-лист для разработчика

При верстке таблицы на любой CRUD-странице проверьте:

- [ ] Обернута ли таблица в `<div className="rounded-md border bg-card">`?
- [ ] Имеют ли `TableHead` классы `h-10 py-2`?
- [ ] Имеют ли `TableCell` класс `py-1`?
- [ ] Добавлен ли `hover:bg-muted/50` к `TableRow`?
- [ ] Используется ли `align-top` для ячеек с потенциально многострочным контентом?
- [ ] Отсутствуют ли избыточные отступы (`py-4`, `py-6` и т.д.)?

Следование этому правилу гарантирует, что все таблицы в Cool ERP будут выглядеть профессионально, компактно и единообразно, обеспечивая максимальную эффективность работы пользователя с данными.
