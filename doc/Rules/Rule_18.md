# Правило №18: Умные toast-уведомления с навигацией (Правило №23?)

После успешного создания или обновления записи система **ОБЯЗАТЕЛЬНО** должна определить, на какой странице пагинированного списка эта запись физически находится, и предоставить пользователю удобный способ к ней перейти. Простого уведомления «Успешно создано» недостаточно.

**СТРОГИЙ ПОРЯДОК ДЕЙСТВИЙ (АЛГОРИТМ):**
1. СНАЧАЛА вызвать `refetch()` для обновления данных текущей страницы.
2. ПОТОМ проверить, есть ли запись на текущей странице.
3. Если запись на текущей странице → **подсветить строку** (согласно Правилу №17).
4. Если записи нет на текущей странице → **найти её в полном списке** и показать toast с кнопкой **«Перейти»**.

---

### 1. Обоснование (Почему это важно)

В системах с пагинацией (например, 10 записей на странице) и сортировкой (по алфавиту или дате) новая запись может попасть на 5-ю страницу, в то время как пользователь смотрит на 1-ю. 
* Если просто показать toast «Роль создана», пользователь не поймет, куда делась запись, и будет вынужден листать страницы вручную.
* Умный toast с кнопкой «Перейти» мгновенно переносит пользователя на нужную страницу, создавая ощущение бесшовного и интеллектуального интерфейса.

---

### 2. Обязательные требования к реализации

#### 2.1. Использование прямой функции API (НЕ хука)
Для поиска записи в полном списке (Шаг 4) **ОБЯЗАТЕЛЬНО** использовать прямую функцию API, экспортированную Orval (например, `readRolesRolesGet`), а **НЕ** React Query хук (`useReadRolesRolesGet`). 
*Почему:* Хуки React нельзя вызывать внутри обработчиков событий или колбэков (это нарушает Rules of Hooks). Прямые функции — это обычные async-функции, которые идеально подходят для разовых запросов.

#### 2.2. Расчет целевой страницы
Если запись найдена в общем списке, номер страницы вычисляется по формуле:
`targetPage = Math.ceil((foundIndex + 1) / limit)`

#### 2.3. Toast с кнопкой действия (Action)
Toast-уведомление при переходе на другую страницу **ОБЯЗАТЕЛЬНО** должно содержать кнопку действия (`action`), которая меняет состояние пагинации (`setPage(targetPage)`).

### 3. Примеры кода

#### ✅ ПРАВИЛЬНО: Полная реализация умного callback-а в родительской странице

```tsx
import { useToast } from "@/components/ui/use-toast";
import { Button } from "@/components/ui/button";
import { readRolesRolesGet } from "@/api/generated/roles/roles"; // ✅ Прямая функция Orval

// ... внутри компонента RolesPage ...

const { toast } = useToast();
const limit = 10;

// Callback, который мы передаем в модалку (Правило №19)
const handleRoleSaved = async (id: string, name: string) => {
  try {
    // ШАГ 1: Обновляем данные текущей страницы
    const { data } = await refetch();
    const currentItems = data?.data?.items || [];

    // ШАГ 2: Проверяем, есть ли запись на текущей странице
    const isOnCurrentPage = currentItems.some((item) => item.id === id);

    if (isOnCurrentPage) {
      // ШАГ 3А: Запись здесь — подсвечиваем строку (Правило №17)
      setHighlightedRoleId(id);
      setTimeout(() => setHighlightedRoleId(null), 3000);
      
      toast({ title: "Роль успешно обновлена" });
    } else {
      // ШАГ 3Б: Записи нет на текущей странице — ищем в полном списке
      // Используем ПРЯМУЮ функцию API с большим лимитом
      const fullListRes = await readRolesRolesGet({ limit: 1000, skip: 0 });
      const allItems = fullListRes.data?.items || [];
      
      const foundIndex = allItems.findIndex((item) => item.id === id);

      if (foundIndex !== -1) {
        // Вычисляем номер страницы
        const targetPage = Math.ceil((foundIndex + 1) / limit);
        
        // ✅ КРИТИЧЕСКИ ВАЖНО: Toast с кнопкой навигации
        toast({
          title: "Роль успешно создана",
          description: `Запись "${name}" находится на странице ${targetPage}`,
          action: (
            <Button 
              variant="outline" 
              size="sm" 
              onClick={() => {
                setPage(targetPage); // Меняем страницу
                // Подсветка сработает автоматически через useEffect после загрузки новой страницы
              }}
            >
              Перейти
            </Button>
          ),
        });
      } else {
        toast({ title: "Роль создана, но не найдена в списке" });
      }
    }
  } catch (error) {
    console.error("Ошибка в handleRoleSaved:", error);
    toast({ variant: "destructive", title: "Ошибка обработки результата" });
  }
};
```

#### ❌ НЕПРАВИЛЬНО: Наивный подход (Антипаттерн)

```tsx
// ❌ ГРУБОЕ НАРУШЕНИЕ ПРАВИЛА №18
const handleRoleSaved = (id: string, name: string) => {
  // ❌ Мы просто показываем тост, не проверяя, где находится запись.
  // Пользователь на 1-й странице, запись на 5-й. Он не знает, что делать.
  toast({ 
    title: "Роль создана", 
    description: `Запись "${name}" успешно добавлена.` 
  });
};
```

### 4. Нюанс: Подсветка после перехода по кнопке «Перейти»

Когда пользователь нажимает кнопку «Перейти», страница изменится (`setPage(targetPage)`). Сработает `useEffect`, который вызовет `refetch()`. После этого новая запись появится на экране. 

Чтобы она подсветилась, нужно сохранить `highlightedRoleId` в стейте, и использовать `useEffect`, который сработает после обновления данных на новой странице:

```tsx
// В компоненте RolesPage
useEffect(() => {
  // Если есть ID для подсветки и данные загрузились
  if (highlightedRoleId && data?.data?.items?.some(i => i.id === highlightedRoleId)) {
    // Запись появилась на экране — запускаем таймер подсветки
    const timer = setTimeout(() => setHighlightedRoleId(null), 3000);
    return () => clearTimeout(timer);
  }
}, [data, highlightedRoleId]);
```

### 5. Чек-лист для разработчика

При написании callback-а `onXxxSaved` в родительской странице:

- [ ] Вызывается ли `await refetch()` в самом начале функции?
- [ ] Проверяется ли наличие записи на текущей странице через `.some()`?
- [ ] Если запись есть — вызывается ли установка `highlightedId`?
- [ ] Если записи нет — используется ли **прямая функция API** (из `@/api/generated/...`) для поиска в полном списке?
- [ ] Правильно ли вычисляется `targetPage` через `Math.ceil((index + 1) / limit)`?
- [ ] Содержит ли `toast` кнопку `action` для перехода на вычисленную страницу?
- [ ] Обернут ли весь блок в `try/catch`?

Следование этому правилу превращает стандартный CRUD-интерфейс в интеллектуальную систему, которая всегда помогает пользователю найти только что созданный объект, независимо от объема данных и настроек сортировки.
