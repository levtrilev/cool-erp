# Правило №23: Алгоритм умной навигации и подсветки после создания/обновления (Правило №18?)

Обработчики сохранения в родительской странице (callback-и, приходящие из модалок: `onItemCreated`, `onItemUpdated`) **ОБЯЗАТЕЛЬНО** должны следовать строгому 4-шаговому алгоритму. Это необходимо для того, чтобы пользователь всегда понимал, где физически находится только что созданная или измененная запись в пагинированном списке.

**СТРОГИЙ ПОРЯДОК ДЕЙСТВИЙ:**
1. СНАЧАЛА вызвать `await refetch()` для обновления данных текущей страницы.
2. ПОТОМ проверить, есть ли запись на текущей странице.
3. Если запись на текущей странице → **подсветить строку**.
4. Если записи нет на текущей странице → **найти её в полном списке** и показать toast с кнопкой "Перейти" на нужную страницу.

---

### 1. Обоснование (Почему это важно)

В системах с пагинацией и сортировкой новая запись может попасть на 5-ю страницу, а пользователь в этот момент смотрит на 1-ю. 
* Если просто показать toast "Успешно создано", пользователь не поймет, куда делась запись.
* Если слепо подсветить строку, подсветка не сработает, так как элемента нет в DOM текущей страницы.
* Умная навигация решает эту проблему, автоматически находя запись и предлагая пользователю переместиться к ней.

---

### 2. Обязательные требования к реализации

#### 2.1. Использование прямой функции API (НЕ хука)
Для поиска записи в полном списке (Шаг 4) **ОБЯЗАТЕЛЬНО** использовать прямую функцию API, экспортированную Orval (например, `readRolesRolesGet`), а **НЕ** React Query хук (`useReadRolesRolesGet`). 
*Почему:* Хуки React нельзя вызывать внутри обработчиков событий (это нарушает Rules of Hooks). Прямые функции — это обычные async-функции, которые идеально подходят для разовых запросов в колбэках.

#### 2.2. Расчет страницы
Если запись найдена в общем списке, нужно вычислить номер страницы, на которой она находится, по формуле:
`targetPage = Math.ceil((foundIndex + 1) / limit)`

#### 2.3. Toast с действием
Toast-уведомление при переходе на другую страницу должно содержать кнопку действия (`action`), которая меняет состояние пагинации (`setPage(targetPage)`).

### 3. Примеры кода

#### ✅ ПРАВИЛЬНО: Полная реализация умного callback-а

```tsx
import { useToast } from "@/components/ui/use-toast";
import { Button } from "@/components/ui/button";
import { readRolesRolesGet } from "@/api/generated/roles/roles"; // ✅ Прямая функция Orval

// ... внутри компонента RolesPage ...

const { toast } = useToast();
const limit = 10;

// Callback, который мы передаем в модалку
const handleRoleSaved = async (id: string, name: string) => {
  try {
    // ШАГ 1: Обновляем данные текущей страницы
    const { data } = await refetch();
    const currentItems = data?.data?.items || [];

    // ШАГ 2: Проверяем, есть ли запись на текущей странице
    const isOnCurrentPage = currentItems.some((item) => item.id === id);

    if (isOnCurrentPage) {
      // ШАГ 3А: Запись здесь — подсвечиваем строку (Правило №17)
      setHighlightedRoleId(id);
      setTimeout(() => setHighlightedRoleId(null), 3000);
      
      toast({ title: "Роль успешно обновлена" });
    } else {
      // ШАГ 3Б: Записи нет на текущей странице — ищем в полном списке
      // Используем ПРЯМУЮ функцию API с большим лимитом
      const fullListRes = await readRolesRolesGet({ limit: 1000, skip: 0 });
      const allItems = fullListRes.data?.items || [];
      
      const foundIndex = allItems.findIndex((item) => item.id === id);

      if (foundIndex !== -1) {
        // Вычисляем номер страницы
        const targetPage = Math.ceil((foundIndex + 1) / limit);
        
        toast({
          title: "Роль успешно создана",
          description: `Запись "${name}" находится на странице ${targetPage}`,
          // ✅ Кнопка навигации внутри тоста
          action: (
            <Button 
              variant="outline" 
              size="sm" 
              onClick={() => {
                setPage(targetPage); // Меняем страницу
                // После смены страницы нужно будет подсветить запись (обычно через useEffect)
              }}
            >
              Перейти
            </Button>
          ),
        });
      } else {
        toast({ title: "Роль создана, но не найдена в списке" });
      }
    }
  } catch (error) {
    console.error("Ошибка в handleRoleSaved:", error);
    toast({ variant: "destructive", title: "Ошибка обработки результата" });
  }
};
```

#### ❌ НЕПРАВИЛЬНО: Наивный подход (Антипаттерн)


### 4. Нюанс: Подсветка после перехода по кнопке "Перейти"

Если пользователь нажал кнопку "Перейти" в toast-уведомлении, страница изменится (`setPage(targetPage)`). Сработает `useEffect`, который вызовет `refetch()`. После этого новая запись появится на экране. 

Чтобы она подсветилась, нужно сохранить `highlightedRoleId` в стейте, и использовать `useEffect`, который сработает после обновления данных:

```tsx
// В компоненте RolesPage
useEffect(() => {
  if (highlightedRoleId && data?.data?.items?.some(i => i.id === highlightedRoleId)) {
    // Запись появилась на экране — запускаем таймер подсветки
    const timer = setTimeout(() => setHighlightedRoleId(null), 3000);
    return () => clearTimeout(timer);
  }
}, [data, highlightedRoleId]);
```

### 5. Чек-лист для разработчика

При написании callback-а `onXxxSaved` в родительской странице:

- [ ] Вызывается ли `await refetch()` в самом начале функции?
- [ ] Проверяется ли наличие записи на текущей странице через `.some()`?
- [ ] Если запись есть — вызывается ли установка `highlightedId`?
- [ ] Если записи нет — используется ли **прямая функция API** (из `@/api/generated/...`) для поиска?
- [ ] Правильно ли вычисляется `targetPage` через `Math.ceil`?
- [ ] Содержит ли `toast` кнопку `action` для перехода на вычисленную страницу?
- [ ] Обернут ли весь блок в `try/catch`?

Следование этому правилу превращает стандартный CRUD-интерфейс в интеллектуальную систему, которая всегда помогает пользователю найти только что созданный объект, независимо от объема данных и настроек сортировки.
