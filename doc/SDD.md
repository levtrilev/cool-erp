Spec-Driven Development (SDD) — это подход к разработке, при котором сначала создаётся спецификация (спека), детально фиксирующая требования, ожидаемое поведение системы, ограничения и критерии приёмки, и только затем начинается реализация. Спецификация становится единым источником истины для всей команды — разработчиков и ИИ-агентов

По сути - это возвращение к прошлому, когда сначала писались все спецификации - только потом код. И при любой правке сначала правится спецификация - потом код. Агент при этом всегда в разработке опирается на спецификацию.

Да, частью спецификации является также описание тестов на соответствие кода спецификации. То есть тесты пишутся до того, как написать код.

В своей работе я использую спецификацию по стандарту https://renar.tech/

На первой странице есть специальный файл для агента. Положите его в свой проект, и в стартовый промпт напишите агенту, что он должен использоваться эту спецификацию для написания документации. 

Также для написания может использовать инструмент https://tausik.tech/

Просто дайте эту ссылку агенту, и попросите установить в проект. После этого появится в проекте ряд команд для разработки. В частности декомпозиция задач по спецификации, и выполнение каждой задачи с созданием тестов и проверкой критериев исполнения.

Логика работы в Таусике соответствует вот этому стандарту. https://senar.tech/

Стартовать можно так. Описываете с помощью агента что Вы хотите в произвольном виде (концепт , или ТЗ - если привычнее), далее даете агенту этот концепт (ТЗ), и просите сделать документацию Ренар, и далее делаете по ней код. После того, как сделаете код - запускаете агента делать тесты, которые уже будут описаны ренар документации.

Изменение делаете так: опять же концепт - что хотите сделать. Далее запускаете агента править Ренар - делать новую версию (да, естественно, всё в гите, версии ренар документации фиксируете). И далее просите агента сделать задачи на приведение кода к новой версии ренар документации.
